# 포맷팅 npm 패키지 개발 절차

## 사용 시점과 준비

포맷팅 기능, 공개 타입, 테스트 또는 빌드·배포 설정을 변경할 때 사용한다. 문서나 주석만 수정할 때는 관련 내용과 링크를 확인한다. 먼저 [저장소 지침](../../../AGENTS.md), [프로젝트 구조](../../../docs/agents/project.md), 현재 `git status --short`와 작업 대상 소스·테스트를 읽는다. 기존 변경과 요청 범위를 구분한다.

여러 세션에 걸치거나 인계가 필요한 작업만 [작업 기록 양식](templates/task.md)을 `_workspace/<작업명>/task.md`에 복사한다. 다른 작업 기록을 덮어쓰지 않는다.

## 분석과 구현

1. 관련 함수와 테스트를 읽어 현재 동작과 호환성 영향을 파악한다. `src/index.ts`에는 여섯 개의 명명된 함수와 `businessNo`, `date`, `number`, `personalNo`, `telNo`, `version`으로 묶인 기본 객체가 있다. API를 변경하면 두 경로와 공개 타입을 함께 확인한다.
2. 날짜 함수의 `dayjs` peer dependency, 날짜·전화번호 함수의 `null`/`undefined` 처리, 번호 함수의 허용 문자와 부분 입력, 숫자 및 버전의 문자열 처리를 변경 범위에 따라 살핀다. 기존 동작을 새로운 요구사항으로 가정하지 말고 관련 구현과 테스트를 확인한다.
3. 타입 전용 심볼은 `import type` / `export type`을 사용한다. 필요한 테스트는 실제 공개 API의 정상값과 변경에 관련된 경계값·오류를 검증한다. 필요하면 README와 예제를 갱신한다. 현재 예제는 패키지에 연결되지 않은 콘솔 출력이다.
4. `dist/`는 추적 중인 생성물이며 직접 편집하지 않는다. Rollup은 `dist/*`를 지우므로 빌드 전에 기존 변경과 미추적 파일을 보존한다. 의존성이나 배포 설정 변경 시 peer dependency, 배포 파일, 소비자 모듈·타입 해석을 확인한다.

## 검증과 인계

[저장소 지침](../../../AGENTS.md)의 타입 검사·lint·테스트를 실행한다. 빌드·공개 진입점 변경에는 빌드를 추가하고 예제 변경 시 예제 타입 검사와 실행을 별도로 확인한다. 배포 설정 변경 시 패키지 파일 목록과 실제 소비자의 `import` / `require` / 타입 해석을 확인한다. 기존 `type: module`과 CommonJS `.js` 출력의 호환성은 가정하지 않는다.

Watchman 오류가 나면 Watchman 없는 테스트와 별도 Rollup으로 대체 확인하되 표준 빌드 통과로 기록하지 않는다. 실패 원인을 코드, 기존 결함, 환경 문제로 구분하고 검사 설정을 완화해 실패를 숨기지 않는다. 마지막으로 diff와 기존 변경 보존 여부를 확인하고, 변경 내용·검증 결과·미확인 사항을 한글로 보고한다.
